THE WUSKALOOSA REPORT — PROJECT HANDOFF
========================================
Last updated: August 21, 2026


WHAT THIS PROJECT IS
---------------------
A static Alabama football sports blog styled like a cross between ESPN College GameDay,
Barstool Sports, and Saturday Down South. Publishing happens entirely through Decap CMS
(a browser-based admin panel) — no editing HTML directly.

Live repo: https://github.com/austinms1298/the-wuskaloosa-report
Deploy target: Cloudflare Pages (connected to the GitHub repo above)


TECH STACK
----------
- Vite 8 (multi-page static site builder, no framework)
- Vanilla JS (client-side routing via window.location.pathname)
- Decap CMS (GitHub backend, markdown posts)
- Cloudflare Pages (hosting + auto-deploy on git push)
- Google Fonts: Oswald (display/headings) + Inter (body)

GETTING STARTED ON A NEW COMPUTER
-----------------------------------
1. Make sure you have Node.js installed (https://nodejs.org — use LTS version)
2. Make sure you have Git installed (https://git-scm.com)
3. Open Terminal and run:

   git clone https://github.com/austinms1298/the-wuskaloosa-report.git
   cd the-wuskaloosa-report
   npm install
   npm run dev

4. Site will be running at http://localhost:5173

To run Decap CMS locally (so you can write/edit posts):
   npx decap-server
   (Run this in a second terminal tab while `npm run dev` is running)
   Then visit http://localhost:5173/admin/

To build for production:
   npm run build
   (Output goes to the dist/ folder)

   git config user.email "9phqjvsppv@privaterelay.appleid.com"
   git config user.name "Austin"

Then to push changes:
   git add -A
   git commit -m "Your commit message here"
   git push origin main

GitHub auth: use your GitHub username + a Personal Access Token (not your password).
Create one at: github.com → Settings → Developer Settings → Personal Access Tokens
→ Tokens (classic) → New token → check the "repo" scope.

Cloudflare Pages auto-deploys every time you push to main.


DECAP CMS — HOW TO PUBLISH POSTS
----------------------------------
Once the site is live on Cloudflare Pages, you'll need an OAuth proxy to log into
the CMS from the live URL. Until then, use local mode (npx decap-server).

The config.yml has placeholders you'll need to fill in:
  - site_url: https://YOUR-PROJECT.pages.dev   ← replace with your actual Cloudflare URL
  - display_url: same

For OAuth (so CMS works on the live site):
  You need a Cloudflare Worker acting as an OAuth proxy for GitHub.
  Repo: https://github.com/stereobooster/decap-proxy
  Once deployed, add to config.yml:
    base_url: https://YOUR-OAUTH-WORKER.workers.dev
    auth_endpoint: auth


POST FIELDS IN DECAP CMS
--------------------------
When you create a new post in the CMS, you'll fill in:
  - Title
  - URL Slug (lowercase-words-with-hyphens)
  - Publish Date
  - Short Summary (shows as excerpt/preview)
  - Featured Image (not shown on homepage but stored in post)
  - Category: Latest Take / Analysis / Preview / Recap / Culture / Opinion
  - Feature on Homepage: toggle on to make it the big "Latest Wuskaloosa Report" hero take
  - This Week's TV Schedule (PDF): optional — upload a PDF and readers get a download
    button at the top of the post
  - Article body (full markdown editor)

Posts are saved as .md files in src/content/posts/


KEY DESIGN DECISIONS
----------------------
- Logo is "stamped" overlapping the crimson navbar border and the hero image.
  It uses position:absolute with z-index:30, header has overflow:visible.
- Hero image (hero-panel.png) is displayed with height:auto — NO cropping.
  The image was pre-cropped to exactly the right dimensions.
- Schedule card on homepage uses a 3-column symmetric grid (1fr 2fr 1fr) so team
  names are truly centered.
- "THIS WEEK!" is auto-detected: any game within 7 days from today highlights
  automatically. No manual update needed.
- Oswald font (Google Fonts) is used for all display/marker headings.
  Springtown Market was considered but is "Personal Use Only" — would need a
  commercial license from MyFonts before using on a public site.
- Footer sticks to the bottom on short pages via: body { display:flex;
  flex-direction:column; min-height:100vh } + main { flex:1 }
- cssMinify is set to false in vite.config.js to avoid a lightningcss binary
  compatibility issue between macOS and Linux.
